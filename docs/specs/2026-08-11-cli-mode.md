## 目标

把 EmbPilot 的全部 MCP 能力通过 CLI 暴露，与 MCP 共享同一套 `dispatch_tool` 分发逻辑，不重复实现业务逻辑。

## 范围

- Phase 1：`embpilot tool <name> --json '<args>'` one-shot 通用子命令 + `embpilot tools` 列表。
- Phase 2：`embpilot shell` REPL，进程内保持 `SessionManager`，一次连接后连续操作。
- 不做：daemon/client 模式、跨进程会话恢复、GUI、交互式配置向导。

## 命令形态

- `embpilot`（无参数）→ 原 MCP server 启动（保持向后兼容）。
- `embpilot tools` → 列出全部工具名与摘要（来自 `build_tool_definitions()`）。
- `embpilot tool connect_serial --json '{"port":"COM3","baudrate":115200}'`
- `embpilot tool send_command --json '{"command":"help","line_ending":"crlf"}'`
- `embpilot tool export_session --json '{"session_id":"...","target_path":"out"}'`
- `embpilot shell` → REPL：输入 `工具名 {"参数":...}`，支持 `help` / `exit`。

## 模块划分（新增，保持小模块）

- `src/embpilot/cli.py` — argparse 子命令、配置解析、one-shot 执行、退出码。
- `src/embpilot/cli_shell.py` — REPL 循环（读行 → 解析 → dispatch → 格式化）。
- `src/embpilot/cli_format.py` — 结果格式化（人类可读 / `--json`）。
- `src/embpilot/__main__.py` — `main()` 分支：无参数 → `serve`；子命令 → `cli`。
- 复用：`SessionManager`、`dispatch_tool`、`build_tool_definitions`、`EmbPilotConfig`，零业务逻辑重复。

## 行为约定

- 默认输出人类可读文本；`--json` 输出 `CallToolResult` 的 `structuredContent` 原样。
- 退出码：`0` = ok；`1` = 工具失败（`ok:false`）；`2` = 用法/JSON 解析错误。
- 配置参数（`--data-dir` 等）与 MCP server 共用，保证 list/export/search 指向同一数据目录。
- 危险命令确认：one-shot 由用户显式在 JSON 中传 `confirm_dangerous_command`；shell 中结果提示需确认时交互提示，不复制危险命令模式表。
- RAG 工具需要 `embpilot[rag]` 依赖，缺失时给出明确错误提示。

## 测试点

- `tests/test_cli.py`：tools 列表、合法 one-shot、非法 JSON → 退出码 2、`ok:false` → 退出码 1、无活动设备错误、RAG 依赖缺失提示（mock `SessionManager` / 设备工厂，不连真设备）。
- `tests/test_cli_shell.py`：假设备下 connect → send → search → export 连续操作、`help` / `exit`、断线后错误路径。
- 全量 `python -m pytest -q`；不引入 live target。
